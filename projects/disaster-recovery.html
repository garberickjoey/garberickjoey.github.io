PROJECT 04 / RESILIENCE

Backup & Disaster Recovery

A practical recovery framework for a small business environment.

RPO

Define how much data the business can afford to lose and align backup frequency accordingly.

RTO

Define how quickly critical systems need to return to service and prioritize recovery accordingly.

Testing

Backups are only useful if restores work. Schedule and document restore testing.

Recovery priorities

1. Identity/DNS dependencies → 2. Critical business applications → 3. File services → 4. User workstations and lower-priority services.

Document dependencies, recovery procedures, responsible personnel, and validation steps before an incident occurs.
