CASE STUDY / ACTIVE DIRECTORY

Computer Authentication Failures

Sanitized example of investigating repeated computer-account authentication failures in a Windows domain.

Problem

A domain controller was reporting repeated failed computer logons from a workstation.

Investigation

Reviewed Event ID 4625, identified the source system, compared IP/MAC information with asset-inventory, noting the workstation name had been changed just before the authentication failures began. Reviewed the computer account in Active Directory, and tested the workstation's secure channel. Noted the workstations secure channel was broken.

Event ViewerPowerShellADUCnslookupARP

Approach

Start with the evidence in the domain controller logs, verify the workstation's network identity, then validate DNS and the machine trust relationship.

The Fix

Attempted to remediate the issue using the PS command: 


                    Test-ComputerSecureChannel -Repair -Credential domain\administrator

Confirmed that the secure channel had been repaired, and monitored for any more authentication failures from the target system

Lesson

Authentication problems can originate below the authentication layer. DNS, addressing, naming, machine identity, and domain trust all need to agree.
