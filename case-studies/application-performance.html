Application Performance Investigation

A structured approach to recurring desktop application problems.

Investigation

Start with the user's exact symptoms and timing. Check running processes, resource utilization, application state, services, dependencies, updates, and relevant event logs. Reproduce the issue when possible before changing multiple variables.

Evidence

Task Manager, Event Viewer, application logs, process/service state, system resource usage, and dependency health can turn a vague “the application hangs” report into a specific technical problem.

Lesson

Good troubleshooting is controlled experimentation: establish a baseline, change one meaningful variable, test, and document the result.

Example Scenario

An end user reported extreme slowness while using Adobe Acrobat

The Investigation

Confirmed that after opening the application, the PC did begin to run slower than when using different applications. Looking at resource utilization, when Acrobat was open memory utilization jumped to almost max. When looking at the running processes, I noticed that Acrobat was creating an abnormal number of the same process during startup. Additionally, I discovered that Acrobat had recently updated, around the same time that the issue was first reported.

The Fix

Taking all of this into account, I used the application instasller to perform a repair, after which I was able to confirm that Acrobat's resource utilization was within an acceptable range.
