Connectivity Troubleshooting

A repeatable troubleshooting method for connectivity problems.

The Problem

I have found that end-users often have difficulty describing connectivity issues. There are many variables in play and the only information that the user will give is "it's not working". This is the step by step framework that I apply when troubleshooting connectivity issues.

Layered workflow

1. Physical: link state, cabling, switch port, wireless association.

2. Local configuration: IP address, subnet mask, gateway, DNS servers.

3. DHCP: lease information, scope availability, reservations and options.

4. DNS: forward/reverse lookup, correct records, authoritative server, client cache.

5. Routing: gateway reachability, route table, VLAN path and firewall policy.

6. Application: test the actual service rather than stopping at ping.

Real Example

An end user reported intermittent network connectivity issues. I began by verifying the user's workstations physical path to the gateway. I was able to verify the cable path to the access switch, and the cable path from the access switch to the gateway. When looking at the switch, I noticed the uplink port on the access switch was flapping. It was also worth noting that the port flapping was causing changing spanning tree topology. I was able to identify this as a potential cause of the intermittent issues. From there, I switched the uplink port on the switch and continued my workflow. I was able to confirm that the workstation was reaching the correct DHCP server, and recieving a correct IPv4 address. I confirmed the workstation was reaching the correct DNS server and the server was operating normally. From there, I was able to validate gateway reachablility and reviewed firewall rules for that zone to rule out the possiblility of routing issues. I was also able to confirm essential application function with the user. After monitoring, it appeared that changing the uplink port on the access switch fixed the issues the user was experiencing. A ticket was submitted for assesment and replacement of the access switch with the failing port.
